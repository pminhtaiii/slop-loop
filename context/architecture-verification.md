# Runtime Verification, Review, and Limits

For changes, establish a pre-edit baseline, apply a controlled patch, run focused and regression checks, check public API compatibility where relevant, and validate the final diff. Review begins only after required verification passes. An applied patch without required passing evidence is incomplete.

The reviewer examines the diff against acceptance criteria and repository conventions for logic errors, edge cases, security concerns, missing tests, and unsupported changes. The reviewer has read-only authority. Reviewer iteration, repair cycles, and expensive actions must have explicit limits; repair uses new tool, test, or review evidence and returns through verification before delivery. When a budget is exhausted or no safe next action exists, stop and report the blocker. The review node retains a sanitized `TaskState.reviewFindings` snapshot (up to 16 findings, 2,048 UTF-8 bytes per message, and 16,384 serialized UTF-8 bytes overall), with truncation marked. Only coder `propose-repair` prompts include the snapshot matching `latestReviewRef`, explicitly marked as untrusted reviewer model output; other coder purposes and reviewer prompts are unchanged. State validation and transport admission enforce the bounds. A later review replaces the snapshot, including empty accepted findings; invalidating review authority excludes historical findings from prompts while retaining them for operator inspection. Controlled prompt and review-repair tests cover this behavior; real-model repair quality is not established.

Each run should have traceable workflow-node, tool-call, skill-invocation, result, error, approval, verification, repair, and review records. Record metadata and only sanitized, bounded approved command details under [runtime_policy.md](runtime_policy.md); never include raw prompts, raw tool output, or protected payloads. Record per-run token usage and cost estimates so evaluation can explain how the final state was reached. Target acceptance evidence is listed in [the verification matrices](../docs/progress-checker-matrices.md).
