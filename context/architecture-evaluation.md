## Feature 007 Phase 4–5 surfaces

Feature 007 Phase 4–5 adds three controlled-tier surfaces on that same graph/service. `src/runtime/evaluation-diagnostics.ts` defines bounded stage/component/attribution vocabularies plus a frozen sanitized record; `src/uc03/graph-diagnostics.ts` supplies the stage mapping and record construction, and `src/uc03/graph.ts` attaches one to a non-complete or unconfirmed-transition result, degrading unrecognised stage or component to `unknown` rather than guessing a cause. T038 extends that record construction: a recognised bounded coder-boundary refusal carried as `REAL_PROFILE_GENERATION_INVALID: <code>` becomes an observed category — `PROPOSAL_INVALID:<code>` reports `model-output`/`model`, an inspect `TOOL_ERROR` or `CHECK_NOT_CONFIGURED`/`CHECK_ADMISSION_REQUIRED`/`CHECK_RESULT_INVALID:<code>` refusal reports `repository-tool`/`tool`, and `MODEL_ERROR` or `MODEL_UNCERTAIN:<code>` reports `provider`/`environment` — with confidence `observed` and a fixed reason code, labelling only the observed category and never a proven root cause. Unrecognised reasons, and the existing state-accounting, approval-issuer and host-snapshot rows, stay `workflow`/`unknown`/`route-incomplete`. `eval/uc03/compare.ts` gains a tagged `compareWorkflowEvaluations` that refuses a pair on any failed identity guard (suite, contract version, mode, selection, manifest, cardinality, repository, grader, pinned initial repository, pinned expected outcome) and reports changed factors, null (never zero) usage deltas and mirrored selection/suite acceptance. Per-case repository, grader and pinned initial-repository identity are three separate guards; an identity the reports never observed (`null`) is reported as an unverified guard and refuses the pair rather than comparing equal, so two not-run reports cannot claim compatibility. `src/runtime/console-server.ts` serves the same `EvaluationService` over `node:http` bound to `127.0.0.1` with exact Host/Origin, an operator token, a 64 KiB body cap and serialised mutations, taking UC-05 approval/decision as an injected port rather than reimplementing it, and comparing either through an injected comparison port or, when none is injected, over a supplied workflow-report lookup; `src/runtime/console-page.ts` renders the operator document with `textContent`-only dynamic writes over static assets in `src/runtime/console-page-assets.ts`. The console now has a trusted same-process host: `createEvaluationConsoleHost` in `src/runtime/evaluation-console-host.ts` composes one readiness, graph, `EvaluationService` and console server, and `evaluate serve --host <path>` (`src/cli/evaluate.ts`, `src/cli/evaluate-console.ts`) starts it. Production serve requires real-ready provenance from `prepareUC03Host` and refuses controlled-ready or mock assemblies with `HOST_CONSOLE_UNAVAILABLE`; malformed arguments are rejected before the host module loads, validation precedes listening, shutdown is bounded, and a real-ready serve holds no workflow reports. The page projects only bounded allowlisted workflow-report fields via `textContent` (invalid or missing values show `unknown`, an ungraded report is custom), the result pane shows only allowlisted receipt/decision fields rather than raw JSON, a sanitizer strips C0/C1, bidi and line-separator characters, and artifact IDs are validated before fetch. Separately, the page renders a generated graph clarification group (1–16 questions) as `textContent`-only controls and submits one answer per question in question order, bound to the group id, digest and current version; a group that is answered, replaced or gone retires its answer idempotency key, while an identical retry of the same unanswered group reuses it. One controlled loopback HTTP journey drives a single composed host/service/graph with the approval port a test double over scripted owner approval; its second attempt re-runs the delivered task, so the comparison is compatible/REGRESSED rather than two independent repairs. The open halves remain: no browser has driven the page (the page checks use a `node:vm` fake DOM), a successful full CLI serve was witnessed only through declared-real shell plumbing and not a real-ready acceptance, console comparison succeeds only in controlled composition (the host supplies a live-service report lookup and `console-server.ts` maps the page's `guarded`/`strict` selection onto `strictSameConfig` over it, while an injected comparison port still takes precedence; the graph binds workflow reports only on controlled-ready routes, so a real-ready serve comparison can only refuse with `WORKFLOW_REPORT_NOT_FOUND`), and sessions are process-local. The report carries one bounded `diagnostic` string, now composed from the graph's structured record's bounded component/attribution/reason codes; the record's evidence refs and milestone kinds are still dropped at that boundary.
