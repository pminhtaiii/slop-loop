# Evaluation Surfaces and Controlled Harness

## Controlled test-only ports

Controlled test-only ports in `tests/runtime/support/uc03/` simulate state, approval, model, repository and reviewer behavior with explicit finite profiles and mock provenance. They do not implement the real adapters or execution boundaries described in [architecture.md](architecture.md).

The restored [v0.2 entry](../src/uc03/graph-v02.ts) takes explicit production ports, checks required callable surfaces and provenance before dispatch, then uses the shared graph runner. [Host bootstrap](../src/runtime/uc03-host-bootstrap.ts) validates delivery pins and assembles without invoking ports; [workflow driver](../eval/uc03/workflow-driver.ts) selects this entry explicitly while retaining separate legacy controlled dispatch. The separate mock-only host assembly returns a tagged controlled-ready result and its versioned controlled runner cannot admit real-declared effectful ports; a controlled driver binding refuses a real evaluation context. Generation validates the canonical model context before v0.2 dispatch without a graph-side claim. Inspect results feed bounded observations into a freshly admitted next turn under the existing agent call/time limits; request identity reuse refuses. Feedback forwards the material-replan port. The direct evaluation shell parses operator references and resolves the host file's `assembly` module reference as a factory; a caller-supplied assembly wins outright, and every unresolved assembly — absent reference, absent file, absent or throwing factory, throwing getter, non-object result — collapses to one named prerequisite gap with no path and no exception text. An absent assembly is a gap, never a mock fallback. Assembly-ready is not behavior conformance or real execution authority; full traversal, approval-context consumption and real owner/profile gates require their own evidence.

## Feature 007 Phase 4–5 surfaces

Feature 007 Phase 4–5 adds three controlled-tier surfaces on that same graph/service. `src/runtime/evaluation-diagnostics.ts` defines bounded stage/component/attribution vocabularies plus a frozen sanitized record; `src/uc03/graph-diagnostics.ts` supplies the stage mapping and record construction, and `src/uc03/graph.ts` attaches one to a non-complete or unconfirmed-transition result, degrading unrecognised stage or component to `unknown` rather than guessing a cause. `eval/uc03/compare.ts` gains a tagged `compareWorkflowEvaluations` that refuses a pair on any failed identity guard (suite, contract version, mode, selection, manifest, cardinality, repository, grader, pinned initial repository, pinned expected outcome) and reports changed factors, null (never zero) usage deltas and mirrored selection/suite acceptance. Per-case repository, grader and pinned initial-repository identity are three separate guards; an identity the reports never observed (`null`) is reported as an unverified guard and refuses the pair rather than comparing equal, so two not-run reports cannot claim compatibility. `src/runtime/console-server.ts` serves the same `EvaluationService` over `node:http` bound to `127.0.0.1` with exact Host/Origin, an operator token, a 64 KiB body cap and serialised mutations, taking UC-05 approval/decision and comparison as injected ports rather than reimplementing them; `src/runtime/console-page.ts` renders the operator document with `textContent`-only dynamic writes over static assets in `src/runtime/console-page-assets.ts`. The two real halves remain open: the console has no `serve` CLI entry yet and the page has not been driven in a browser, and the comparison port is still injected by tests alone with no production adapter mapping the page's `guarded`/`strict` selection onto `strictSameConfig`. The report carries one bounded `diagnostic` string, now composed from the graph's structured record's bounded component/attribution/reason codes; the record's evidence refs and milestone kinds are still dropped at that boundary.
