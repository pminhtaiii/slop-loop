# Active-task handoff

Before editing, establish scope from the feature task graph or approved maintenance brief, then register the coordinator or worker in shared state. Start the managed session with `agent-work.mjs` and render only its progress file under `.agent-work/<date>/<session-id>/`. All linked worktrees share the ignored `.agent-work/state/active-tasks.json`. [`active_task.md`](../../context/active_task.md) is the static command page; session progress stays in the selected session folder. `tasks.md` remains the only feature task-status ledger. Use the primary helper with `--root <worker-checkout>` when needed.

Use unique owner and task IDs. Register current coordinators before dispatch. For new existing-checkout workers, use contributor preparation with `--register`, explicit sessions and exact owned paths via repeated `--owned-path` options; opt factory assignments in with `--factory-managed`. New worktree workers retain reserve/bind/readiness; keep worker paths disjoint and later or blocked feature tasks in `tasks.md`. Assignment and status report progress, not authorization. `active_task.md` lists lifecycle commands. A worker handoff captures index and worktree hashes for its owned paths; the coordinator verifies them before integration or publication. Workers hand off local results and do not complete contributor work or edit another checkout's Markdown.

Update the next action at meaningful checkpoints; keep blocked or interrupted entries registered. For an intentionally started background job, follow [yield and resume](pr-workflow.md#yield-and-resume) and retain its ID and next action. Explicit `publish --mode full` stays in the foreground; the detached runner cannot force full mode. Pending local gates or remote CI keep the assignment active without requiring an active agent turn. Workers use handoff; coordinators use the publication workflow, app-link receipt, and finish gate. Finish requires a clean current PR, retained publication evidence, app link, a two-axis review receipt for the current head, all current-head CI required by the publication policy, and no merge blocker; pending CI stays active under the public PR watcher. The human merge decision remains separate. For user-authorized local-only/no-push work, use the worker handoff and report local evidence without claiming PR completion. Archive terminal work only after integration and durable evidence: preview the unique ignored output, then apply; only that matching terminal assignment may be cleared. Retain active/blocked assignments. Keep docs/verification/ archives ignored and local; never force-add them or require them to exist for CI. Tracked docs may link immutable history or label local paths as code. If archive creation is interrupted, retry the same command and output; do not overwrite or substitute. The helper does not commit or push. See the [PR workflow](pr-workflow.md) for contributor completion and paired publication.

Use the compact assignment list first. `recovery-report.mjs` correlates registry state with checkpoints, worktree changes, and receipts, but agent liveness remains `unknown` without host evidence. Reassign only for an explicit recovery decision; retain predecessor evidence and the linked successor. Use `agent-context.mjs resume` for dependency or authorization details. Follow the [workspace guide](workspace.md) before worktree creation or cleanup; session finish blocks its active/blocked assignments and worktree retirement checks the whole checkout. Cleanup previews by default and requires explicit authorization to apply; archival never removes a worktree or its evidence. Legacy migration is explicit and preserves snapshots; shared writes use one lock. Keep rendered assignments out of unrelated PRs and workers within their owned paths.
