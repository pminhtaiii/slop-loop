# Confine repository tools to one validated checkout

The MVP workspace is one developer-selected Git checkout, even when Slop Loop starts in a subdirectory. Trusted application code discovers its root with `git rev-parse --show-toplevel`, resolves and validates the physical path, and seals that root for the task; admission fails outside a valid checkout. Repository tools cannot cross into sibling or nested repositories, including submodules. Tracked and untracked nonignored files are eligible for repository access, while ignored paths and `.git` internals are excluded. Existing secret-path denials still apply. This gives the agent the whole selected codebase without making a launch subdirectory or another repository an implicit authority source.

Repository content reads and mutations reject hard-linked files in the MVP because canonicalizing one hard-link path cannot establish where its other names are. In-repository symlinks may be followed for reads, list, and search only when their resolved targets remain in the same selected repository and pass path policy; traversal must stop cycles. The checkout itself may reside on a mounted volume, but nested mount crossings, Linux bind mounts, Windows junctions, and equivalent reparse boundaries are denied. Pipes, devices, sockets, and other nonregular content targets are rejected. An OS-temp handoff document is outside the workspace and is not readable through repository tools; the developer can paste its contents into a new prompt. A future explicit external-file import would require a separate authority decision. Files larger than 64 KiB yield an explicit `read_file` size-limit result rather than partial content; the model-visible result cap is 64 KiB. `search_code` caps total output at 32 KiB and matches at 200, bounds returned lines at 4 KiB and searched files at 4 MiB, and marks omitted matches as truncation. Per-tool output contracts retain smaller limits for unrelated tools.
