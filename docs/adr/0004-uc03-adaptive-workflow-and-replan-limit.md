# UC-03 high-level gates with adaptive execution

Accepted during the UC-03 design discussion on 2026-10-15 in Asia/Saigon (UTC+07:00), with the approval-gate decisions and discussion closure confirmed on October 16 in the same timezone. Use a hybrid bug-fix workflow: the harness enforces high-level stage prerequisites and completion gates, while the agent chooses its reasoning approach and permitted tool calls within each stage. Do not prescribe a fixed sequence of individual searches, reads, or investigative calls. This preserves flexibility when evidence changes without making tool authorization or completion depend on model judgment alone.

The first localized bug-fix slice validates the task, investigates and reproduces the bug, records a fix plan, applies controlled changes, verifies, obtains read-only review, and delivers evidence. Existing acceptance, baseline, policy, test-protection, verification, and completion requirements remain binding. Changes following verification require renewed verification for the resulting repository state. Unexpected evidence can lead back to investigation and a revised strategy within the task's remaining allowances.

Allow at most three material replans after the initial plan per task. A replan materially changes the recorded fix strategy in response to new evidence; another file read, an additional search, or an implementation adjustment within the same strategy does not count. Replanning does not reset repair, reviewer, token, cost, or other execution budgets, including across runs and restarts. When a fourth material replan is necessary, stop and report the incomplete outcome and blocker rather than executing that strategy. Exact accounting transitions and the remaining finite budget values require specification.

UC-03 owns the bug-fix behavior and replan semantics. Shared foundation enforces execution and limits; UC-04 owns persisted accounting and recovery, and UC-05 owns approval decisions. This decision does not authorize implementation or add a general-purpose planning system.

On 2026-10-16 in Asia/Saigon (UTC+07:00), the owner accepted the pre-edit gate: investigation permits bounded reads, searches, and reproduction commands. Before production-code edits, record acceptance criteria, baseline evidence, required checks, and a fix plan. The agent may add a regression test during reproduction to demonstrate the pre-fix failure; existing tests remain protected from weakening.

For the MVP, require human approval of the diagnosis and proposed fix plan before applying the fix. Present the observed failure and reproduction evidence, suspected cause and affected locations, proposed changes, and verification approach so the developer can assess whether the agent understood the bug. Do not substitute automatic plan approval for this checkpoint. Human plan approval does not establish correctness or waive tool policy, action-specific approvals, verification, or review. The exact approval binding remains to be agreed with UC-05.

Every material replan requires renewed human approval before edits under the revised strategy. Bounded investigation may continue within the existing task scope and tool policy; minor implementation adjustments within the approved strategy do not require renewed plan approval. A material replan consumes one of the three task-scoped replan allowances. Human approval does not replenish that allowance.

If the user rejects a plan, wait for their feedback rather than autonomously generating alternative plans. The user may request a revision or end the task. A requested revision that materially changes the fix strategy counts toward the same three-replan cap; wording clarification does not.
