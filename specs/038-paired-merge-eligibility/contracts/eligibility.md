# Contract: Documentation Eligibility Preview

## Invocation and result

`node scripts/agents/paired-merge-eligibility.mjs [--root <checkout>]` evaluates the existing pair for the checkout's current feature branch. `--help` describes this invocation. Duplicate/unknown arguments, including `--apply` or `merge`, are rejected before inspection. No caller-supplied readiness or evidence file is accepted as proof.

Return JSON with the fields in [data-model.md](../data-model.md). A well-formed ineligible observation may exit 0; callers must read `status` and `eligible`. Invalid invocation exits nonzero. Reasons use stable codes and bounded explanations, at most 100 path reasons and 200 characters per explanation. Output carries public PR identity and opaque submission-side number/revisions, without private repository names or URLs. `mergeEnabled` is always false.

## Pair and readiness admission

1. Locate the checkout root and primary checkout through bounded read-only Git inventory using the same executor/environment as every other Git read. Read current branch/HEAD and clean tracked/untracked status. Require a supported feature branch and existing configuration for public `origin/development` and private `submission/development`, distinct repositories and expected visibility. Read effective remote URLs and normalize their repository identities; read each repository's live visibility. Bind normalized identities and visibility in the canonical observation, keeping private identity internal. Existing authenticated access is used for GET operations only.
2. Read retained workflow and pair records from their existing primary-checkout `.agent-work/pr-workflow/<branch-without-feat-prefix>.json` and `.agent-work/paired-prs/<branch-with-slashes-replaced>.json` locations. Validate directory components and records as regular/unlinked paths. Missing paths never cause creation. Require matching branch, targets, complete pair phase, exact public publishedHead/sourceHead, sourceTree, mirrorHead, PR identities and paired marker. Preserve all accounting.
3. Read both exact retained live PRs and their live base/head OIDs. Require identities, URLs, branch/base names, open/non-draft/non-fork state and `MERGEABLE`/`CLEAN` on both. Compare public HEAD to retained published/source heads and submission head to retained mirrorHead; cross-check every cached workflow submission identity/provenance field against the pair and live evidence. Repository names are case-insensitive. Verify the marker in submission metadata. Match live commit-tree OIDs to each other and retained sourceTree. Prove the live submission base is an ancestor of its head with a read-only comparison of the exact base/head and repeat that observation; clean mergeability alone does not prove freshness. This clarifies the existing exclusion of behind submission PRs without requiring local mirror objects.
4. Read complete public check-run pages and select the latest run by numeric ID for each of the four existing required names, restricted to exact public head and `github-actions`. Require completed/success for all four. Bind run IDs as well as names, heads, app, status and conclusion. Submission CI does not drive this decision.
5. Require local immutable public base/head objects and public base ancestry of head. A missing object waits; a behind/diverged head blocks. No fetch is performed. Classify the entire immutable public diff below.
6. Before returning eligible, repeat configuration/record bytes, local branch/HEAD/status, effective `origin`/`submission` remote URLs and normalized identities, live repository visibility, live PR metadata including bases/states, tree and required-check observations. Any material difference, new failure or unavailable reobservation refuses eligibility. Compare canonical observations, independent of response ordering. Private repository identities and URLs remain internal and never enter reports or diagnostics.

## Documentation classification (`docs-v1`)

- At least one and at most 100 changed paths; full raw diff output must fit the command output bound. Use NUL-delimited raw records with `--no-renames`, validate every record, and refuse malformed/truncated data.
- Case-sensitive allowed paths: root `README.md`, or `.md` files below `docs/user/` and `docs/guides/`. Canonical slash-separated components contain only letters, digits, underscores, hyphens and dots; no empty, dot, dot-dot or hidden components.
- Reject governance directory components `agents`, `adr`, `context`, `specs`, `policy`, `policies`, `contracts` and governance basenames `AGENTS.md`, `CLAUDE.md`, `SKILL.md`, `GLOSSARY.md`, `CONTRIBUTING.md`, `SECURITY.md`, `CODEOWNERS` case-insensitively even inside an allowed directory.
- Admit only added or modified mode-100644 regular files, with unchanged mode for modifications. Reject deletes, renames/copies, mode/type changes, executable modes and symlinks. `--no-renames` exposes a rename as add/delete and therefore refuses it.
- Read blobs by immutable object IDs, not worktree paths. Both existing before content and after content must be valid UTF-8 prose, at most 64 KiB each and at most 1 MiB combined. An added file has an absent preimage, which is valid and contributes zero bytes; do not attempt to read its all-zero preimage object ID. Reject NUL and control characters other than tab/LF/CR.
- Conservatively reject any triple-backtick or triple-tilde sequence, any line starting with four spaces or a tab, and any `<` character in either before or after content. This intentionally sends code fences, indented examples and raw HTML to manual review, including harmless examples. It is a lexical exclusion, not semantic certification.

## Read-only and failure boundary

The implementation calls only bounded Git reads and authenticated `gh` reads through structured executable/argument arrays with shell disabled. Every Git child, including root/worktree discovery and imported-helper calls, receives `GIT_NO_LAZY_FETCH=1` and `GIT_OPTIONAL_LOCKS=0`; missing promisor objects must fail instead of fetching. Do not call imported `repository()` or another helper whose direct executor bypasses these environment and timeout/output requirements. No mkdir, write, lock creation, save helper, fetch, push, PR ready/merge/edit, issue writes, or branch-protection changes are part of this command. Temporary test setup may write fixtures; invoking preview may not.

Missing/pending evidence yields `WAITING_EVIDENCE`; known identity mismatch, stale/raced observations, failed CI, malformed responses and merge blockers yield `BLOCKED`; unsupported change classification yields `MANUAL_REVIEW`. Every refusal has `eligible: false`. Bound timeout/output/parse errors and sanitize diagnostics. No automatic retries or cached eligibility are used.

## Required pagination fixtures

Focused contract tests must include multiple check-run pages with a required check present only on a later page, and a newer failed run on a later page superseding an earlier success for the same required name. Malformed or incomplete pagination must refuse eligibility. These fixtures verify both complete collection and selection across page boundaries; a single-page fixture is insufficient.
