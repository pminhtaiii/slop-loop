# Proposed Contract: uc06-review-context/1

Status: planning proposal; G-OWNER/G-AUTH required. Additive beside canonical v0.1 ReviewResult and v0.2 provider admission; no keys or digest inputs are added to owner wire records.

## 1. Trigger, API and compatibility

Only existing UC-03 Review after required passing checks is supported. Existing `UC03ReviewerPort.review(task,diff,evidence,request,admission)` and `createRuntimeReviewer` remain the generation path. No generic BugTask, autonomous tool loop or pre-plan provider diagnostic is synthesized.

Proposed additive TypeScript seams (implemented only after release):

- `ReviewContextV1` / `ReviewObservationV1` and `ReviewProfileV1` in src/contracts/review.ts; runtime parsers/admission in src/uc06/validation.ts.
- `prepareReviewContext(inputs)` in src/uc06/context.ts returns `ready({context,evidence}) | blocked({reasonCode})`. Inputs are host-selected measured facts and validated owner records; it has no filesystem/model/state mutation capability.
- Existing `buildReviewerSnapshot(..., binding, boundContext?)` and `reviewerContextDigest(..., binding, boundContext?)` gain the same optional final ReviewContextV1. Legacy absent-argument output stays byte-identical. With context, append a deterministic synthetic `review/context.json` SourceEvidence item, plus existing `review/diff.patch`. Reserve both names: caller-supplied evidence using them is refused.
- RuntimeReviewerOptions gains optional `resolveReviewContext(task,diff,request)` returning the host-prepared `{context,evidence}` or undefined. Its presence selects UC-06; undefined result fails closed, never legacy fallback. The returned evidence must equal the passed evidence byte-for-byte, and task/diff/request bindings must match. Snapshot/digest use that exact context.
- UC03GraphConfig and UC03GraphConfigV02 gain optional `reviewContext` host resolver keyed by current task/state/diff. UC03ReviewerAdmissionRequest gains optional `reviewContext` and `evidence` so host admission mints the exact snapshot digest. graph-v02.ts forwards the resolver to the existing factory and shared config using one request-keyed prepared record; it must not resolve a second independently changing context. These are host-only graph supplements, not fields in ProviderAdmissionContextV02. New UC-06 route requires configured resolver and matching reviewer resolver; unchanged legacy route remains explicitly non-UC-06.
- Graph constructs/validates ReviewObservationV1 from the current bound context, canonical result and owner outcome/evidence records. It retains it through the existing evidence owner and supplies it as an optional companion in host-controlled completion inputs. Completion on the UC-06 route requires an acknowledged current companion. No mutable last-call getter, model output, bare evidence ID or serialized copy can mint that acknowledgment.

Ownership: Tai accepts reviewer/transport/graph/completion seam changes; assigned UC-06 owner supplies pure types/assembly/validation. Observation storage uses the explicit UC-04-owned supplement in section 6, not the baseline-only BaselineEvidenceWriter. G-OWNER covers its proposed agreement and controlled doubles; G-DELIVERY requires an actual owner implementation. UC-06 implements no storage engine.

## 2. Closed context record

All fields below are required except explicitly optional; reject unknown properties recursively. Safe identifiers are nonempty <=128 UTF-8 bytes. Digests use canonical SHA-256. Repository paths are canonical non-protected relative paths <=512 bytes; no links/outside/protected-data access. The record is immutable.

| Field | Value / meaning |
|---|---|
| schemaVersion | literal uc06-review-context/1 |
| binding | Exact fields: taskId, runId, repositoryId, workspaceId, baseRevisionDigest, headRevisionDigest, diffDigest, criteriaDigest, checkSetDigest, verificationDigest, conventionsDigest, evidenceDigest, profileDigest |
| authority | Exact fields: taskStateVersion, controlVersion, epoch, decisionAuthorityGeneration, planDecisionRef, planBindingDigest. Nonnegative safe integer versions; approved current D1 and separately validated historical D0 ancestry |
| profile | ReviewProfileV1 below, content digest equals binding.profileDigest |
| verification | baselineRef and results array of {evidenceId,checkId,phase,outcome,repoDigest,diffDigest,contentDigest}; required results must pass, current head/diff, configured purpose/check and criteria. Baseline original-revision binding is validated separately through existing baseline/ancestry, not relabeled current |
| conventions | Array of {path,revisionDigest,contentDigest,evidenceRef}; host-selected inventory (possibly empty only by explicit profile declaration), current approved content |
| evidence | Array of {evidenceRef,path,revisionDigest,contentDigest,kind}; kind requirement/convention/verification/source; exactly matches approved excerpts plus referenced owner evidence |
| contextDigest | Canonical SHA-256 of this record excluding contextDigest |

binding.evidenceDigest hashes the ordered supplied SourceEvidence list; binding.verificationDigest hashes verification; binding.conventionsDigest hashes conventions. Criteria digest hashes canonical task acceptanceCriteria and constraints. Profile/record hashing uses canonical helpers; diffDigest uses exact unchanged diff bytes via the same canonical helper as current reviewer. Base/head are measured repository snapshot digests, not guessed Git SHA or model statements.

This companion's criteriaDigest includes constraints by design; it never replaces the existing canonical approval/completion criteria digest over acceptanceCriteria alone. Validate the canonical owner binding with its unchanged helper and independently validate the companion against both current criteria and constraints. No owner digest/schema is silently redefined.

SourceEvidence sent to current ModelPort must have headRevisionDigest because its validator requires current revision. Old-side source comes from the exact diff captured at head with base identity in binding, not a falsely relabeled base source excerpt. Baseline/check records remain acknowledged original owner records; synthetic context describes their origin and safe metadata, not their raw logs or hidden test bodies. Selected current verification diagnostics use sanitized current-revision evidence. Truncated required excerpt or missing required source span blocks; optional omissions are explicit profile metadata.

Profile exact fields: profileId, profileVersion, promptVersion, promptDigest, requiredConventionPaths, optionalEvidenceRefs, maxDiffBytes, maxContextBytes, maxEvidenceItems, maxEvidenceBytes, maxFindings, maxMessageBytes, maxOutputBytes, maxResponseBytes. All bounds are finite positive safe integers; maxResponseBytes must be >= maxOutputBytes; lists are unique/safe/bounded by maxEvidenceItems. No universal production numeric default. Controlled tests explicitly pin 48 KiB diff, 64 KiB context, 32 items/32 KiB evidence, 16 findings, 2 KiB message, 16 KiB model-content output and 128 KiB total HTTP response; these are test fixtures only. Provider timeout/token/billable/cost and task/run review limits remain required canonical admission bounds, not duplicated ledger fields.

promptDigest/version pin trusted role instructions/schema, excluding untrusted evidence. Existing transport selects trusted branch from role=reviewer and purpose=final-review, includes constraints, and rejects mismatched profile/template identity before network. Unknown role/purpose/schema cannot choose coder fallback on this route.

DeepSeekTransportOptions gains optional host-only `reviewPrompt` with exactly version, digest, maxOutputBytes and maxResponseBytes. The first two identify the compiled trusted reviewer template; both limits must match selected ReviewProfileV1. UC-06 host composition requires this pinned configuration at creation of the existing reviewerModelPort/transport and compares it with the same profile used by the graph context resolver. Repository evidence cannot populate or alter those options; no new ProviderRequest or HostModelTransportPayload wire fields. Reviewer-purpose invocation on a missing/mismatched configured profile refuses before network; legacy coder behavior stays compatible. Input-token admission includes actual selected system-template bytes.

Transport reads nonstreaming-protocol HTTP response through a bounded body reader: count actual received bytes before appending/decoding, stop/cancel at maxResponseBytes+1 and never call response.text() or parse the outer JSON on an over-limit body. Content-Length is at most an early rejection hint, never authority to skip actual counting. Missing/unreadable body, invalid UTF-8, timeout or oversized body after possible network dispatch returns charged uncertainty with a fixed safe reason, no raw content and no retry; unknown usage keeps the conservative owner hold. Once a bounded valid outer message supplies usage, measure UTF-8 bytes of decoded model content against maxOutputBytes before returning it for inner verdict JSON.parse. Over-limit model content returns invalid with observedUsage, so owner settlement charges the actual call. Reviewer repeats its content/count/message checks defensively; it is not the first unbounded read/parse barrier. Escaped outer JSON bytes and decoded content bytes are different counters.

## 3. Findings, output and evidence semantics

Model content remains exactly `{status:"accepted"|"findings",findings:[...]}`; each finding remains canonical `{file,line,side,severity,message,evidenceRef}`. No revision/action/tool field in model output. UC-06 requires evidenceRef even though legacy validator allows omission.

- line is a positive safe integer and must be changed on selected old/new side of exact bound diff. Normal modify/add/delete paths only. Old maps to baseRevisionDigest; new to headRevisionDigest. Observation supplies that mapping; invented per-finding revision is an unknown-field rejection.
- severity is error (incorrect/security-critical behavior), warning (concrete significant risk/missing required test), info (nonblocking advice). This is product severity, distinct from contributor P0–P3.
- message states the concrete defect/risk/advice, supporting consequence and relevant requirement/convention; nonempty reasoned prose, not hidden reasoning.
- evidenceRef must resolve in the admitted evidence index or host-registered diff artifact at that exact binding. Require contentDigest/current origin and an anchor supporting the rationale. Unsupported references reject; deterministic validation proves resolution/location, while independent grading judges semantic support/correctness.
- status accepted contains no error/warning; findings requires >=1 error/warning; info-only can be accepted. Any bad finding invalidates whole response; no dropping bad findings to convert to accepted.
- Enforce output bytes before JSON parsing/forwarding, count/message bounds before report creation, and protected-content filtering on every field. No raw model output in failure reports.
- A nonempty ModelProposal.actions array, tool-call/patch/write payload or unknown field is invalid, even if embedded content says accepted. No action capability is dispatched.

Diff admission checks full bounded complete text before existing parser: same-path modify or /dev/null add/delete only; reject rename/copy, binary, mode-only/mixed unsupported metadata, quoted/ambiguous paths, malformed/overflow hunk arithmetic and empty diff. Do not silently skip unparsed sections. Every diff entry is represented or whole review refuses.

## 4. Lifecycle and accounting

1. Host loads current task/control/approval, measured immutable base/head/diff and acknowledged verification/conventions/criteria/evidence. Check required passes and current D1/original D0 ancestry before provider work.
2. Validate bounds/content/identities; prepare immutable context; snapshot and reviewerContextDigest mint the exact same evidence/context used at dispatch. Bind to current owner request/receipt/generation, reviewer role and final-review purpose.
3. Use existing HostModelPortV02 only: one claim, beginAttempt, pre-network multi-budget reservation and receiver one-shot/outcome chain. UC-06/graph does not reserve/claim a second time.
4. Serialize immutable snapshot acquisition and mutable admission through existing owner read fence/leases; reobserve authority immediately before dispatch. Missing trusted protocol refuses rather than claim post-check alone prevents a race.
5. On response, account observed usage even for invalid content, retain uncertain holds for missing usage/settlement, then validate result and current candidate/authority. Permit expected accounting-only version changes from the exact provider chain; do not mistake own settlement for repository drift. Any unrelated task/control/policy/revision drift withholds current acceptance.
6. Persist safe observation through existing evidence owner with acknowledgment. Completion requires canonical review plus current companion bound to independently resolved owner record/checks. Late/stale/uncertain observations cannot become accepted by serialization or copying.
7. Findings go to existing repair, which obtains fresh action authority, preserves allowances and invalidates affected evidence. After repair: Verify then new Review with new request/context/admission. Material replan needs renewed approval and existing task cap; no reviewer writes.
8. Unknown dispatch/outcome/settlement or failed observation persistence blocks continuation until owner reconciliation. Replaying identical completed request can return retained result without new charge; conflicting ID denies. New retry gets new admitted ID only after prior reconciliation and remaining allowance. Pause/rejection stops all reviewer work.

## 5. Observation and outcomes

Closed ReviewObservationV1: schemaVersion=uc06-review-observation/1, contextDigest, binding, authority, reviewId, providerRequestId, status, reasonCode, result, accountingRefs, evidenceTier.

status is accepted/findings/invalid/stale/blocked/uncertain. result is canonical ReviewResult or null (pre-dispatch block/unknown result); accepted/findings require nonnull matching canonical result and acknowledged observed settlement. reviewId is null only if no result exists; providerRequestId null only before a request was allocated. accountingRefs is bounded exact owner refs, empty only for proven pre-dispatch no accounting. evidenceTier is unit/controlled/real-provider/real-integration; quality and restart are separate evaluation claims.

Safe reasonCode is a closed vocabulary: OK, FINDINGS, INPUT_UNSUPPORTED, REQUIRED_EVIDENCE_MISSING, BINDING_STALE, AUTHORITY_UNAVAILABLE, LIMIT_INVALID, BUDGET_EXHAUSTED, MODEL_OUTPUT_INVALID, PROVIDER_TIMEOUT, USAGE_UNCERTAIN, EVIDENCE_UNACKNOWLEDGED. Do not expose exception/provider payloads. Status/reason consistency is validated. Canonical invalid/unknown cannot be promoted to accepted; harness final completion remains independent.

## 6. Proposed UC-04 supplement: uc06-review-evidence/1

ReviewEvidencePortV1 is declared beside companion types in src/contracts/review.ts and validated in src/uc06/validation.ts. UC-04 owns its implementation/durable storage; this is a new explicit supplement, not an assertion that current baseline storage supports it. It has `reviewEvidenceApiVersion: "uc06-review-evidence/1"`, provenance mock/real, `persistObservation(request)`, `loadObservation(request)` and `recoverObservation(request)`. All are asynchronous typed closed unions. Host config UC03GraphConfig and UC03GraphConfigV02 gain optional `reviewEvidence`; graph-v02 forwards the same instance. An opted-in UC-06 route requires it before dispatch, actual callable/version/provenance checks, and real owner delivery for production. The reviewer itself never gets this write port. BaselineEvidenceWriter stays unchanged.

Persist request exactly: observation (ReviewObservationV1), observationDigest (canonical hash of complete observation), expectedAuthority (the current post-provider authority tuple from section 2), and idempotencyKey (safe <=128 bytes). Owner validates task/run/repository/workspace/head/diff/context identity, current control and exact provider journal status under its existing serialization boundary before committing. Expected authority is the post-call owner observation, not the pre-call tuple echoed from context. Accepted/findings require exact settled observed provider chain; invalid/stale/uncertain may be retained as audit but never supply accepted authority. Paused/fenced/conflicting requests reject. No task/control version or budget change is introduced by the evidence write.

Persist result is exactly one of: `{outcome:"acknowledged",ack}`, `{outcome:"conflict",reasonCode}`, `{outcome:"denied",reasonCode}`, `{outcome:"uncertain",operationRef}`. Safe reasons here are BINDING_STALE, AUTHORITY_UNAVAILABLE or MODEL_OUTPUT_INVALID; operationRef is an opaque bounded owner key, no raw exception. Same key/same full digest replays identical acknowledgment without rewriting/charging; same key/different bytes conflicts. Unknown commit remains uncertain until owner lookup, never assumed durable. The owner atomically commits observation, acknowledgment and a candidate/provider-request discovery index in the same durable transaction before acknowledging; a separate later graph CAS is not that atomic link. This supplement specifies owner storage semantics, not a UC-06 index/ledger implementation.

Ack exact fields: schemaVersion="uc06-review-evidence/1", receiptId, taskId, runId, repositoryId, workspaceId, headRevisionDigest, diffDigest, contextDigest, providerRequestId (nullable for pre-request audit), observationDigest, storeRecordVersion (positive safe integer), and committed=true. It acknowledges immutable exact content, not completion or action authority. No prompts/labels/credentials or raw source are stored in this safe record. Owner may retain protected underlying permitted artifacts under existing access policy.

Load request exactly: taskId, runId, providerRequestId (nullable), contextDigest, observationDigest and expectedAuthority (current tuple). Result is `{outcome:"found",observation,ack}`, `{outcome:"missing"}`, `{outcome:"conflict",reasonCode}` or `{outcome:"denied",reasonCode}`. Lookup uses owner-retained bytes/current authority, not a caller-supplied acknowledgment. Source validation verifies both schema/digests and every identity, canonical result, current head/diff/criteria/check/context, exact provider chain and current approval/control. Changed evidence cannot be relabeled as current by an old receipt. A malformed/mismatched/unavailable reply blocks completion; no model/task object or copied ACK is an independent lookup.

Recovery request exactly: taskId, workspaceId, repositoryId, headRevisionDigest, diffDigest, expectedAuthority (current tuple), and optional operationRef (owner-issued uncertain write key). It deliberately requires no providerRequestId/contextDigest/observationDigest or graph-only locator. These candidate facts are independently remeasured and checked against current owner task identity; no arbitrary repository/model query or cross-task browsing. A supplied operationRef must belong to that exact task/candidate or deny.

Recovery result is `{outcome:"found",observation,ack}`, `{outcome:"missing"}`, `{outcome:"uncertain",operationRef}`, `{outcome:"conflict",reasonCode}` or `{outcome:"denied",reasonCode}`. Under owner serialization, resolve the latest authoritative final-review provider request for this task/candidate across runs and its atomic discovery index. Only its exact committed observation/ACK may be returned; missing latest evidence cannot fall back to an older accepted observation. An open/uncertain reviewer request or evidence commit yields uncertain and prevents provider retry; ambiguous ordering/multiple incompatible matches conflicts. Found supplies original runId/providerRequestId/contextDigest/observationDigest from owner-retained bytes; caller then performs exact loadObservation and normal current-binding/settled-chain validation. No stale receipt can become current by discovery.

If termination occurred after provider settlement but before any observation commit, recovery may correctly return missing. Report IMPLEMENTED_UNVERIFIED/EVIDENCE_UNACKNOWLEDGED, preserve the charged provider outcome and stop; missing evidence is not verified non-dispatch and cannot authorize replay/refund. Owner reconciliation of unresolved operations remains the existing journal's responsibility. Successful continuation is permitted only from exact committed recoverable evidence; recovery cannot reconstruct a verdict from prose or run a fresh reviewer to hide a lost result.

Graph persists the validated current observation after provider settlement and before its Review→Repair/Deliver transition. It retains safe refs through existing task evidence refs/graph companion, then loadCompletionPredicateInput freshly loads and validates current bindings. After a lost ACK, lost graph CAS or TaskState-only restart with no locator, it calls recoverObservation using current measured candidate, never the provider, then loads the exact discovered record. If its own subsequent CAS increments state version, compare actual current tuple while preserving original receipt/content; allow exact documented own-chain deltas only. Missing/uncertain/denied/conflicting discovery/write/load keeps IMPLEMENTED_UNVERIFIED and no additional provider call. Current task/run/authority must permit continuation; original observation run is journal-linked history, not new-run permission or budget reset.

T002 owns public supplement types/runtime validators, including recovery request/results and forged/unknown-key/ACK tests. T006 owns host injection/consumption/completion and controlled in-memory double tests/runtime/support/uc06/review-evidence.ts: acknowledged round trip, replay/conflict, commit then lost ACK before graph CAS, fresh consumer with TaskState only and no locator, exact candidate discovery/load with zero provider replay, unknown commit/operationRef, latest-missing versus older accepted, post-settlement/pre-persist missing, cross-task candidate and authority drift. Double storage is retained separately from reconstructed graph consumers; no durable claim. T001 requires exact supplement agreement; G-DELIVERY requires actual atomic-index adapter conformance, and T013 actual kill immediately after durable observation/index commit but before ACK/CAS, including withheld graph refs. No UC-06 task owns UC-04 implementation or a parallel store.
