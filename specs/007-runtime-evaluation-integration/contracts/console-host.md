These are trusted callable capabilities, never serialized input. Construction does not execute provider, command, task or approval effects.

Before opening a listener, validate admitted profile identity against configuration and exact ready identity, catalog digest and configured IDs. Call `routesFor` once with the exact readiness and catalog. Require exactly one route for every configured case, each matching its catalog entry and the same readiness object; custom route, if present, uses that readiness. Validate callable task/direction resolvers and positive finite coder budgets bounded by the admitted limits. Reuse existing readiness, profile and route validation; do not relabel mock ports, manufacture admission or weaken existing validation to start the server. Missing/inconsistent delivery, identity, catalog, route or token yields a bounded unavailable result before listening or workflow dispatch. Getter/factory failures at this trusted assembly boundary are translated to fixed safe reasons, with no raw exception/config/module/token data.

Do not create another graph for reporting, controls or comparison, or introduce a report/session store.

Keep the token host-issued, entered locally into the existing page, held in memory and sent only through the existing header; never put it in output, URLs, repository/config JSON or reports. Preserve exact Host/Origin, mutation-token, bounded JSON, serialized mutation, safe-ID, no-CORS, no-store and digest-checked artifact allowlist behavior. This contract does not require a redesign of the existing read-access policy.

Runtime `close` is safe to call repeatedly. Partial startup/listen failure cleans up and returns a fixed safe error without an orphan listener. No model or owner operation is automatically retried. Process exit discards current Map-backed graph/service sessions; browser refresh within that process is not restart acceptance.
