## (b) Production UC-04 implementations

All four honour the T019-agreed surfaces (`decisions.md:13`, `host-composition.md:38-58`). They build on the existing durable store and lock (`src/persistence/store.ts`, `src/persistence/lock.ts`); no second engine, no in-memory fallback.

1. **Read fencing (T040).** `createStateReadFence(port: DurableStatePortV02, binding)` returns a `GuardedReadOwnerPort`. `observeReadControl` reads the persisted control head for the bound task/workspace/repository and returns `{controlVersion, mode, holdRef, fencingGeneration, policyDigest, readAllowed}`; `readAllowed` is true only for `runnable` with no hold. `fenceReadControl(observation)` re-reads the head under the task lock and returns a receipt only when every field still matches; any drift returns `null`. A pause or fence after observation therefore refuses the read (agreed "read fencing").
2. **Exact-operation lookup (T040), routed per effect class (T058).** Every uncertain outcome carries an `operationRef` with an owner prefix, and continuation resolves it only through that owner. No generic lookup guesses across stores.

   | Effect | operationRef producer and durable record | Lookup and outcomes | Consumer |
   |---|---|---|---|
   | Provider attempt | `uc04-journal:<claimId>`; UC-04 claim/attempt journal (`DurableStatePortV02.claim/beginAttempt`) | T040 `lookupOperation` under the journal rule below: `committed` for a recorded outcome or a bound settled reconciliation; `absent` only when the claim was closed unattempted; otherwise `unknown`. Nothing queries the provider, so a dispatched-but-unrecorded call stays `unknown` | T058 gate: `unknown` blocks the task permanently in this scope; a fresh task is the only path forward |
   | Patch attempt | `uc04-journal:<claimId>` for the repository attempt | Same T040 lookup. Repository reconciliation of an unrecorded patch is not implemented (`host-composition.md:64`), so it stays `unknown` | T058 gate: blocked; zero `applyPatch` replays |
   | Material replan | `uc04-journal:<operationId>` written by T044 in the same atomic journal write as the transition | T040 `lookupOperation`: `committed` (state and receipts) when the transition landed; otherwise `unknown`, including a lost replan write that left no record. Never `absent` | T058 gate: `unknown` blocks in this scope; `committed` goes to the existing replan consumer (`src/uc03/replan.ts:271`) |
   | Baseline write | `uc04-baseline:<sha256 of key and content digest>`, issued by T041 before the write | T041 `lookupWrite`: `committed` with the original acknowledgement when the final file exists with that content digest; `absent` when neither the final nor the temporary file exists; `unknown` otherwise (temporary file present, wrong digest, unreadable) | T058 gate, then the existing baseline adapter |

   **Journal rule** (every `uc04-journal:` ref). A ref with no journal record is `unknown`. `absent` applies only to a claim (provider attempt or repository patch/command) closed unattempted: closure refuses a claim with an attempt, so nothing was dispatched. A closed claim that still carries an attemptId is `unknown`. A settled claim is `committed` only when its `settlement {reconciliationId, receiptDigest}` binding names a valid committed reconciliation; a binding that names a missing or invalid reconciliation is `unknown`. A committed reconciliation without that binding on the claim is never `committed`.

   `lookupOperation` reads only the journal, `lookupWrite` reads only the evidence store, and neither writes or re-executes anything. A ref with an unknown prefix is `unknown`.
3. **Baseline evidence store (T041).** Implements `OwnerBaselineEvidenceDelivery` (`baseline-evidence-adapter.ts:31-36`) with `provenance: 'real'`. `persist` writes the canonical candidate and its digest atomically, keyed by `(taskId, workspaceId, repositoryId, evidenceId)`; it returns `durable` only after the atomic rename succeeds, `denied` for a conflicting ID with different content, and `uncertain({operationRef})` when the write outcome is unknown. `load` returns `found` with byte-identical content and acknowledgement, `missing`, or `uncertain`. `lookupWrite(operationRef)` resolves an uncertain write as routed in item 2, without rewriting. A rename that committed but lost its acknowledgement is reported `committed`, with the acknowledgement recomputed from the stored record.
4. **Approval store interop (T042).** Missing decision lookups return the consumer's `invalid/unknown-decision`; first request creation returns `pending` with the committed request-event ID; initial control takes the actual task repository/workspace mapping instead of the `default-repo/default-ws` seed. Durable-file semantics are unchanged; no compound-transaction claim.
5. **Authority publication and recovery admission (T043).** `DurableStatePortV02.publishAuthority(options)` persists an authority publication with monotonic generation and returns the receipt shape `control-v02.ts:18-25` validates; `loadAdmission(decisionId)` returns the persisted admission record recovery needs. Construction authenticity uses a dependency-neutral registry, `src/foundation/production-journal-registry.ts`, which imports nothing: a module-private `WeakSet` with `registerProductionJournal(port)` and `isProductionJournal(value)`. The `DurableStatePortV02` constructor registers itself when built with `provenance: 'real'`. That constructor is the only call site of `registerProductionJournal` in `src`, and a test enforces it. Approval code imports only the registry, never `src/persistence/`. The existing edge `state-port-v02-storage.ts:7` → `approvals/control-v02.ts` therefore gains no reverse edge, and the module graph stays acyclic (`context/code_standard.md:31`).
6. **Material replan transaction (T044).** `createMaterialReplanPort({ state, verifyDirection })` implements `MaterialReplanPortV02.accept` under the task lock: recompute the canonical candidate `FixPlan` digest before any mutation; check CAS on prior task/control versions, the expected prior/next count and a UC-05-verified current revise direction; then one atomic journal write records the allowance, the plan transition to renewed approval and invalidation of prior edit/decision/review authority. Same request replay → `already-accepted` with the identical committed state and receipts and no charge; same proposal ID with different content or digest → `denied`; the fourth material replan → `denied` before mutation; unknown write outcome → `uncertain({operationRef})`, resolvable only through `lookupOperation`.

## (d) G-PROFILE operator profile

**Location.** Outside every checkout, so it can never be staged: `%USERPROFILE%\.slop-loop\uc03-real-tier\` (Windows) or `~/.slop-loop/uc03-real-tier/`. The loader (T047) refuses a profile, state root or artifact path that resolves inside the repository root. The environment variable `UC03_REAL_TIER_PROFILE` names the profile file, because the CLI calls `createHostAssembly()` with no arguments (`src/cli/evaluate.ts:237`).

**Credentials.** Read once from `process.env.ANTHROPIC_API_KEY` inside the assembly and passed only to `createDeepSeekTransport` (`deepseek-transport.ts:38-41`). The name is fixed, not configurable. The value is never logged, persisted, hashed into a digest, used as the `endpointDigest` key, written to a report, or passed to any child process (T048's spawn allowlist). An absent or empty variable makes readiness `unavailable` with reason `credential-missing`. Retained-evidence checks scan every retained file for the key's bytes and fail without printing it.

**Endpoint and model (operator-pinned).** The user serves the model from a self-hosted Anthropic-compatible endpoint, not `api.deepseek.com`. The assembly resolves exactly one endpoint and one model id, then freezes both for the process:

- **Endpoint.** The profile's `provider.endpoint` (an exact `<base>/messages` URL), or, when that is absent, `process.env.ANTHROPIC_BASE_URL` plus `/messages` (the variable holds a `http://<host>:<port>/v1`-shaped base). If both are set and differ, readiness refuses (`endpoint-ambiguous`). If neither is set, the current pinned `https://api.deepseek.com/anthropic/v1/messages` stays the default.
- **Validation** (T047 at load and T049 in the transport, both required). The value must be an absolute URL with no username, password, query or fragment, and its path must end in `/messages`. The protocol must be `https:`, or `http:` only when the profile sets `"allowInsecureHttp": true`; otherwise the profile refuses to load (`insecure-endpoint-unacknowledged`). The transport stores the normalized `href` at construction and compares it exactly before every `fetch`. No model-, task-, request- or browser-supplied URL is ever accepted, and redirects stay refused.
- **Model id.** The profile's `provider.model`, or else `process.env.ANTHROPIC_MODEL`; if both are set and differ, readiness refuses (`model-ambiguous`). The user's id is `po/deepseek-ai/deepseek-v4.1-flash-1017` (supplied by the user, as `decisions.md:108` anticipated; it supersedes the earlier `deepseek-flash` alias), and it already satisfies the host file's identifier rule (`src/cli/evaluate.ts:69`). Readiness pins it as `requestedModel` in `host.json`. The transport already records requested and returned identities (`deepseek-transport.ts:317`). The T054 conformance call requires the returned identity to equal the pinned id exactly and stops the campaign on mismatch; the coordinator then asks the user rather than accepting another string.

Where this section and the T028 row name `po/deepseek-ai/deepseek-v4.1-flash-1017`, that is the earlier pin.
- **Two pinning sites change** (T049). The transport's `assertPinnedEndpoint` (`deepseek-transport.ts:89-93`) and the profile's `endpointOf` (`src/runtime/evaluation-profile-primitives.ts:102-106`, today `https` on `api.deepseek.com` only) both accept the operator-pinned endpoint under the same rule, and both keep the current default.

**Cleartext risk.** A plain-`http` endpoint on a public address sends the `x-api-key` header, prompts (which contain repository excerpts) and responses unencrypted. Anyone on the path can read or alter them, and a captured key gives full use of the deployment. `allowInsecureHttp: true` is the operator's explicit acceptance of that risk. Neither the transport nor the profile can make an `http` hop safe. Recommendation: put TLS in front of the deployment, or tunnel it (`ssh -N -L 127.0.0.1:<local-port>:127.0.0.1:<port> <user>@<host>`) and point the profile at `http://127.0.0.1:<local-port>/v1/messages`, where the cleartext hop is loopback-only. Readiness output and evidence records state `transport: insecure-http-acknowledged` whenever the flag is in force.

**Privacy.** This repository is public. No tracked file (docs, tests, fixtures, snapshots, commit messages) may contain the real host, port or full URL. Docs use `http://<host>:<port>/v1`; tests use reserved documentation values such as `http://192.0.2.10:8080/v1` (RFC 5737) or `http://model.invalid:8080/v1`. Readiness output and retained evidence record only `endpointDigest` and the scheme. They never record the URL itself, so evidence copied into a ticket or PR leaks nothing.

- **Keyed digest.** An unkeyed hash of a host and port is easy to brute-force, so `endpointDigest` is HMAC-SHA256 of the normalized URL, keyed by `provider.endpointDigestKey`: 32 cryptographically random bytes as 64 lowercase hex characters, generated locally with `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`, kept only in the out-of-repo profile, required for any non-default endpoint and never serialized, logged or used as digest input. The API credential is never the key. Only the public default `https://api.deepseek.com/anthropic/v1/messages` may use a plain SHA-256. A non-default endpoint without a valid key refuses (`endpoint-digest-key-missing`). The loader also refuses an obviously weak key (`endpoint-digest-key-weak`): fewer than 10 distinct hex characters, any single character in more than 25% of positions, or a string that repeats a pattern of period ≤ 8. Before each commit from a real-tier session, the coordinator runs the quiet staged-tree scanner (T057): `node dist/src/cli/real-tier-scan.js --staged`. Whenever the needle set changes and before every publication of real-tier evidence, it also runs `--all` (Tree). Before each push of a real-tier branch, it runs `--range <base>` (History). It never uses `git grep` with real values.

- **Needles.** Derived in memory from the endpoint T047 resolves (profile or environment, whichever is in force): the full URL, the base URL, `host:port`, the host alone, the scheme-less `host:port/<path>`, and the URL-encoded forms of each. Host matches need a non-host character on each side, so `192.0.2.7` does not match `192.0.2.70`. A loopback host (`127.0.0.1`, `localhost`, `::1`, as used by the SSH tunnel) yields no host-only needle, only the port and URL forms. A loopback endpoint hides the remote host, so the operator then also supplies the remote private endpoint in the profile's `privacy.additionalPrivateEndpoints` (`string[]`, never committed); each entry yields needles derived exactly like the endpoint's, and a loopback endpoint with no entry is a scan error (`tunnel-endpoint-missing`). The default `api.deepseek.com` endpoint yields no needles, because it is public.
- **Port rule.** The resolved port is a needle only when it is explicit and is not 80 or 443. A bare number is too noisy to match everywhere (sizes, counts, line numbers, IDs), so the port matches only in two contexts, with digit boundaries on both sides: (1) after a host-like token, as `:<port>` or `%3A<port>`, where the token is a dotted name or IPv4 address, `localhost` or a bracketed IPv6 address; (2) as the value of a key whose name contains `port` (case-insensitive), written as `<key>: <port>`, `<key> = <port>` or `"<key>": <port>`, quoted or not. The port alone in prose, or after a token with no dot, is not flagged. research.md records this trade-off.
- **Credential.** Taken only from `ANTHROPIC_API_KEY` and held in memory as a presence marker. It is never printed, logged, hashed into output or written. When it is unset, the scan has no credential needle and says so in the final line (`SCAN_CLEAN credential-unchecked`).
- **Digest key.** `provider.endpointDigestKey` is a secret needle exactly like the credential: held in memory only, matched in contents and paths, and never printed, logged or written. A hit prints only `DIGEST_KEY_LEAK`.
- **Tree.** `--staged` scans exactly the candidate index. Paths come from `git diff --cached --name-only -z --diff-filter=ACMR`, and each blob is read with `git show :<path>`, both through structured argv with no shell. Deletions are skipped, because their bytes are not in the candidate. A rename or copy is scanned under its new path, and the old name is not part of the candidate. `--all` audits the whole index: paths come from `git ls-files -z`, each entry is read with `git show :<path>` through structured argv, and the same needles, path rules and output contract apply. `--staged` stays the per-commit check; `--all` is required whenever the needle set changes (a new endpoint, digest key or `additionalPrivateEndpoints` entry) and before every publication of real-tier evidence, because a needle added later is invisible to `--staged` in unchanged tracked files. `--dir <path>` scans a named directory of retained evidence recursively.
- **History.** `--all` reads only the current index, so it misses a host committed in an earlier unpushed commit and removed by a later one, and it never reads commit messages. `--range <base>` runs before every push of a real-tier branch. It scans every commit in `git rev-list <base>..HEAD`. For each commit it scans the message (`git log -1 --format=%B <sha>`) and every blob the commit adds or modifies: paths come from `git diff-tree --root -r --no-commit-id --diff-filter=ACMR -z <sha>`, and each blob is read with `git show <sha>:<path>`. All git calls use structured argv with no shell. The same needles, path rules and output contract apply. A host removed by a later commit is still reported. A message hit reports location `commit-message:<sha>`.
- **Paths are data.** Every staged or indexed path, and every directory and file name under `--dir`, is scanned (raw and percent-decoded) against the same needles as file contents. A path hit is a leak even when the content is clean, reported at line `0`.
- **Output.** Only `<location>:<line> ENDPOINT_LEAK`, `<location>:<line> CREDENTIAL_LEAK` or `<location>:<line> DIGEST_KEY_LEAK` lines, plus a final `SCAN_CLEAN`, `SCAN_LEAK` or `SCAN_ERROR <code>`. `<location>` is the relative path only when no segment of it matches a needle and it is printable ASCII. Otherwise it is `path-hmac:<first 12 hex digits of HMAC-SHA256(path)>`, keyed by `provider.endpointDigestKey`. An unkeyed hash would let a reader hash guessable paths that contain a private host. That key exists for every non-default endpoint, which is the only case with a private-host needle, and the operator can still match a path locally with the same key. With no digest key (the public default endpoint) the only needle is the credential, and a path that contains a high-entropy credential cannot be guessed, so the location is then `path-sha256:<first 12 hex digits of the path's sha256>`. A matched value, a line's content and a needle are never printed or written anywhere. Raw child-process errors (which can contain paths) are never echoed; only the fixed error code is.
- **Exit status.** 0 clean, 1 leak, 2 scan error (unreadable profile, git failure, a blob read failing for an extant index path, no endpoint resolvable, a loopback endpoint without `privacy.additionalPrivateEndpoints`). Callers treat any nonzero result as blocking.
- **Testability.** Tests feed reserved sentinel endpoints (RFC 5737 / `.invalid`, with a non-default sentinel port) and a sentinel credential, and assert that stdout and stderr contain no sentinel substring on clean, leak and error paths, including for leaks found in paths.

## (e) Usage limits: runaway stop, no economic cap

The user serves the model on their own deployment and asked not to limit usage, so FR-006's "no user economic cap" stands (`spec.md:82`, `decisions.md:51,107`). There is no USD cap, no cross-run spend ledger and no budget command. What remains is a **runaway stop**: finite per-run token and call limits, enforced in code before dispatch and failing closed, as `context/runtime_policy.md:23` requires for every token limit.

| Limit | Default | Enforcement |
|---|---|---|
| Per call | 32,768 input, 8,192 output tokens | Existing profile limits and transport admission (`deepseek-transport.ts:151-152`) |
| Calls per run | 24 (`limits.totalModelCalls`) | UC-04 task accounting (existing) and the run limiter below |
| Tokens per run | 400,000 input, 80,000 output (`runLimits`) | Run limiter below |

**Run limiter (T049).** `createRunUsageLimiter(limits)` is passed to `createDeepSeekTransport` as a new `runLimiter` option and runs inside `execute` after `admit` and before `fetchFn` (`deepseek-transport.ts:277-283`).

1. Key the counters by the request's `(taskId, runId)`. A request without both refuses.
2. Before the call, refuse with `{outcome:'denied', reason:'RUN_USAGE_LIMIT_REACHED'}` when the run has already made `totalModelCalls` calls, or when the run's charged tokens plus this request's admitted maxima would exceed either per-run token limit. This is the transport's existing pre-dispatch path, so UC-04 records an undispatched outcome.
3. Count the call before `fetch`, and charge its admitted maxima as provisional tokens.
4. After the call, replace the provisional charge with the observed usage **only** for a validated 2xx response with parsed usage. In every other case after `fetch` was invoked (timeout, abort, network error, 4xx/5xx/429, malformed or usage-less body), the call keeps its full admitted maxima, so unknown usage never counts as zero.
5. Counters are in-memory, per transport instance. A run never spans processes in this scope, because restart is excluded. A process that starts a new run gets new counters, and UC-04 task accounting remains the durable authority for task budgets (`data-model.md:3`).
6. Absent, non-integer or non-positive limits refuse construction, so readiness is `unavailable` (`run-limits-invalid`).

**Cost reporting.** Each call records usage tokens (or `unknown`) and an `estimate-unverified` cost computed from the placeholder table. Run totals sum only known parts and say `incomplete` when any part is unknown. No figure is labelled actual or billed.

## (h) Failure and recovery

| Failure | Required behaviour |
|---|---|
| Provider timeout after possible dispatch | Transport `uncertain`; the run limiter keeps the full admitted maxima; the UC-04 attempt stays uncertain. No retry; the run ends incomplete. Rerun only by an explicit new operator command on a fresh task |
| Provider 5xx / 429 | Observed failure; usage unknown, so the full admitted maxima stay counted. No retry or backoff loop; the run ends incomplete with a `provider` diagnostic. The operator waits and starts a fresh run |
| Run usage limit reached mid-run | Next call refused before `fetch` (`RUN_USAGE_LIMIT_REACHED`), zero dispatch; the graph ends incomplete and the task stays recoverable |
| Endpoint unreachable / connection refused | Treated as possible dispatch (`uncertain`), no retry; T054 stops after the conformance call fails |
| Insecure endpoint without acknowledgement | Profile refuses to load (`insecure-endpoint-unacknowledged`); zero effects |
| Endpoint or model ambiguous, or URL drift | Readiness refuses (`endpoint-ambiguous` / `model-ambiguous`); a per-call `href` mismatch is denied before `fetch` |
| Returned model identity mismatch, or conformance timeout / 5xx / 429 / unreachable | The campaign ends after exactly one fetch, with a nonzero exit, a sanitized failure record and zero case dispatches. A later `--case` invocation refuses without a matching receipt (T059 gate tests) |
| Container OOM / timeout | Executor reports a failed check with the kill reason; no pass and no retry beyond the existing bounded repair allowance; the container is removed with cleanup that preserves uncertain evidence (T004) |
| Docker daemon absent or image missing | Static assembly stays effect-free and reports `assembly-ready` only. The separate operational preflight (T060; see "Operational preflight and CLI metadata" below) then reports `docker-unavailable` or `image-mismatch` before any task allocation, and probes and runners report not-run with a nonzero exit |
| Uncertain effects | Routed per effect class (§(b)2) through the T058 gate. Baseline write: `committed` resumes from the owner record, `absent` permits a fresh attempt under new authority, `unknown` blocks. Replan: `committed` resumes; a lost write with no record is `unknown` and blocks in this scope. Provider and patch: `committed` resumes and `absent` (a claim closed unattempted) permits a fresh attempt, but a ref with no record or an unrecorded dispatch stays `unknown` and blocks the task permanently in this scope (no provider query, no repository patch reconciliation); the only path forward is a fresh task. Never blind replay (`context/runtime_policy.md:25`) |
| Stale approvals | UC-05 service refuses stale or changed bindings; a fresh decision is required; zero patch or executor effect |
| Credential missing | Readiness `unavailable` (`credential-missing`), zero effects |

## (i) Operational preflight and CLI metadata

**Two readiness stages.** Static assembly (`createHostAssembly()`, T050) is synchronous and effect-free: no spawn, fetch, task write or file write. The resolution it returns adds two optional members the CLI loader validates (T060):

- `metadata`: a frozen, safe projection `{ profileDigest, endpointDigest, endpointScheme: 'https' | 'http', insecureHttpAcknowledged: boolean, model, imageId }`. The CLI accepts exactly these keys, checks each against a fixed pattern (sha256 digests, the identifier rule at `src/cli/evaluate.ts:69`), and refuses anything else (`HOST_METADATA_INVALID`, exit 4).
- `preflight`: an async operational observation, `() => Promise<{ ok: true, dockerServerVersion, imageId } | { ok: false, reasonCode: 'docker-unavailable' | 'image-mismatch' }>`.

**Permitted seam.** The preflight is a trusted host-controller observation, not an agent tool. It runs exactly two fixed argv commands through `structuredSpawn` (no shell, minimal environment, 10 s timeout, 4 KiB output): `docker version --format {{.Server.Version}}` and `docker image inspect --format {{.Id}} <profile imageId>`. Neither value comes from a model, a task or argv. This stays within `context/tools_permissions.md:3` (deterministic enforcement in tools) and `:22` (allowlisted commands only): the model can never invoke it, and it reads no repository content. It also implements `context/runtime_policy.md:15` ("Refuse execution when required isolation cannot be established") before any task allocation.

**CLI integration (T060).** `evaluate preflight` and `evaluate run` call `preflight` after `prepareAssembly` and before any allocation. Readiness output adds `assembly: 'ready'`, `operational: 'ready' | <reasonCode>` and the validated `metadata`; `readinessReport` (`src/cli/evaluate.ts:213-222`) serializes nothing else. When host-file `requestedModel` (`:121`) differs from `metadata.model`, readiness refuses (`HOST_MODEL_MISMATCH`, exit 4). Absent `metadata`/`preflight` keeps today's behaviour for existing controlled assemblies. `src/cli/evaluate.ts` is 20,018 bytes, so host-file loading and assembly resolution move to `src/cli/evaluate-host.ts` first. T051–T054 call the same `preflight` member before their first effect.
