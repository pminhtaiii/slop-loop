# Persistent hybrid retrieval — question-retrieval/1

## Admission and chunking

Only the host may admit an immutable repository snapshot and begin index work. Compare canonical paths and original byte digests under the current repository/workspace, policy and configuration. Apply the existing read guard and protected-content filter before parsing or embedding. Exclude unsafe paths, binary or rejected content and record safe coverage reason codes. Vectors and manifests remain host-only and subject to the same repository access policy. No source bodies in the index or general logs.

The pinned Tree-sitter Python grammar supplies class/function/method boundaries, including decorators and nested names. Include bounded regions for module-level text, approved docs and configuration. Syntax failure falls back to bounded text and flags incomplete definition coverage. Keep definitions intact when they fit. For oversized definitions, prefer complete logical units from the syntax tree (nested definitions, compound statements and statement groups) in source order. Pack adjacent units only when they fit. Recurse into suites for a unit that exceeds a cap. Use whole-line splits only for an indivisible oversized syntax unit or text without usable syntax boundaries. Every emitted chunk remains contiguous and points to its original definition ID, qualified name and full source range. Record part order within that definition; splitting does not create new definitions. Each chunk has at most 60 inclusive lines and 4096 normalized UTF-8 bytes; the full serialized embedding input, including prefix, metadata and special tokens, must fit the pinned tokenizer/model limit. Count before dispatch with truncation disabled. Split again or record an omission if one line or the mandatory input does not fit. Query overflow returns a typed limit result. No partial line evidence.

## Storage and publication

Use one host-owned on-disk SQLite database with pinned sqlite-vec, outside target roots. Scope every lookup to a committed generation for the admitted repository, snapshot, manifest, revision, policy and config. Persist per-file digests, coverage, chunks and vectors. First admission creates an index. On compatible reopen or refresh, diff the admitted manifest by path and original-byte digest. Insert additions, replace modified paths, delete missing paths and keep unchanged chunks and vectors. A rename is removal plus addition. An identical manifest under a compatible binding requires zero corpus embedding. Configuration or policy changes require a compatible rebuild before serving.

Prepare work in bounded batches under host deadlines. Stage candidates outside the serving generation, then apply the complete delta and compare-and-set the expected predecessor/generation binding in one transaction. Failed/interrupted work must roll back or remain invisible. On restart read only committed state and revalidate it against the admitted snapshot before query. A stale generation cannot serve a newer revision. Keep question sessions in memory. Record typed outcomes for busy, stale, unavailable, invalid, exhausted and cancelled. Enforce quotas for files, chunks, vector dimension, batches, memory/cache, disk including staging/journal, concurrency and time. Bound native operations through an isolated host worker and deny further effects after closure. Test pinned dependency loading and on-disk recovery on Windows and configured CI before accepting the store. Report unsupported platform/config as unavailable and reassess the store choice.

## Ranking and evidence

Use finite candidate and scan caps, exact cosine over compatible normalized finite vectors and case-sensitive exact qualified/simple definition names. Exact qualified matches outrank exact simple matches, which outrank semantic-only matches. Recognize symbols from the current question only. Scan left to right for maximal runs of Unicode letters, combining marks, digits, underscores and ASCII dots. Trim leading and trailing dots as punctuation, then accept a run only if each dot-separated component is a valid Python identifier under the pinned grammar. Preserve spelling and case. A dotted run matches a complete qualified definition name only; an unknown dotted run does not contribute its component names. An undotted run matches a complete simple definition name. A name is recognized only if the committed definition metadata contains that match. Deduplicate recognized names and take the union of candidates. A candidate matching several names receives its highest tier once, with no bonus or question-order preference. A query without a recognized symbol uses cosine alone. Rank across the entire compatible generation within the admitted scan budget. If a cap or deadline prevents a complete ranking, return typed exhausted with no scored list; a completed empty list is distinct. Verify stable ordering across more than five tied candidates. Sort within a tier by descending score and then canonical path, startLine, endLine and stable chunk ID. Use one deterministic string ordering independent of host locale. Deduplicate identical chunk identities before truncating to five; ties at the cutoff use the same order as every other rank. Literal occurrences do not gain definition rank. Test punctuation, case mismatches, partial and unknown qualified names, repeated names, multiple recognized names in reversed question order at equal cosine scores, and queries without recognized symbols.

Retrieve from the matching generation once per scored question turn. Freeze identities and provenance before supplemental tool calls. Read ranked spans using the guarded reader and compare actual coordinates/digests before issuing evidence. When a question needs a longer definition, use the original-definition link to select adjacent parts or bounded successive readSpan ranges from that definition in the same snapshot. Each read consumes the existing work/call/output budget, rechecks binding and issues only the lines actually admitted. Report incomplete coverage when a gap or limit prevents reading the necessary logic. Expansion never enlarges a scored result or changes the frozen Recall@5 list. Exact name lookup and bounded guarded search may produce a host coverage receipt for a specific absence investigation only when the relevant eligible scope is complete and current and no unresolved gap could change the result. A miss or low score alone is insufficient.

## Binding changes, retention and accounting

A new trusted snapshot ID with identical canonical manifest, repository/workspace, policy and index configuration may atomically rebind the committed generation after bounded verification, with zero vector-row writes and zero corpus embeddings. Reissue query references under the new binding. Read binding and rows within one pinned DB read transaction; reject superseded results at evidence admission if the current binding changed. A revoked scope fails admission before DB reads and invalidates pending publication. Reclaim inaccessible old generations and abandoned staging through host-owned quota-bound cleanup. Restrict DB and journal access to the host. A policy change invalidates the old derived data and requires cleanup and re-admission before reuse. Test concurrent readers, denied scope and stage reclamation.

Index refresh consumes its own finite host reservation and single writer. Query tokenization, embedding, scan and reads consume the task budget and use the earlier task or worker deadline. Recheck authority, predecessor and reservation just before commit. If the worker dies or commit result is uncertain, block serving from that attempt until bounded reopen verifies committed state against the active binding. A cancelled task cannot start or retry indexing. Independent host refresh requires its own active authority and reservation.

## Scoped absence receipt

The host derives scope from the admitted target and explicit user scope, defaulting to the full eligible repository. Model-selected paths cannot narrow the proof. A host-issued receipt binds repo, snapshot, revision, policy, generation, normalized query digest, canonical scope, exact-definition and guarded literal scan completion and omission reasons. Accept only for a concrete static lookup when both lanes checked scope completely and no candidate or relevant omission exists. Parse failures, protected/unreadable eligible regions, truncation, cap or stale binding that may hide the behavior prevent absence. Behavioral paraphrases and dynamic/reflection lookups without verifiable static scope remain insufficient or clarify. Check receipt freshness before delivery and test partial coverage, unauthorized narrowing and drift.
