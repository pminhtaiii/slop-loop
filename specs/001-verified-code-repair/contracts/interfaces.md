# Shared Interfaces: UC-03 Contract v0.1

**Status**: T001 records accepted logical contract v0.1 and shared-owner agreement in [decisions](decisions.md). T003 provides the executable schema version `0.1.0` in [canonical contracts](../../../src/contracts/foundation/uc03.ts), with conformance vectors in [contract tests](../../../tests/runtime/contract/uc03.test.ts). All later consumers and mocks use these validators; no alternate schemas. Additive changes require contract tests; breaking changes update the version and all consumers before integration. Schema conformance does not establish real adapter, isolation, durability or workflow acceptance.

## Envelope and validation

Requests carry schemaVersion, request/action ID, task/run/workspace ID, expected state version, repository revision/worktree digest and trusted configuration identity. Results discriminate success, needs-info, pending-approval, denied, conflict, exhausted, timeout, error and uncertain-effect. Success includes safe evidence references and new state version when changed. Failures include stable reason and safe next action, never raw payloads. Unknown properties that affect execution are rejected; validate paths, argv, numbers, model responses and restored records at runtime.

Bug input requires repositoryId, goal, observed/expected behavior, reproduction, acceptanceCriteria, constraints and requiredChecks. Host input resolves an approved workspace; model-supplied arbitrary host paths are never workspace authority. Missing criteria/reproduction requests information; ambiguity pauses for confirmation. Check definitions use structured executable and argv, expected purpose/phase and finite config refs, not shell strings.

## Port ownership and semantics

The canonical module separates schema parsing from admission against explicit trusted current context. Its digest helpers use SHA-256 over JSON with sorted object keys; use validated records and preserve patch bytes. Review findings identify old/new diff sides explicitly. Provider dispatch admission requires the authoritative request history and exact persisted multi-budget reservation receipt; a schema-valid request or bare reference grants no dispatch permission. Each port carries explicit `real` or `mock` provenance; `isAdmittedForProduction` rejects mock, missing and invalid markers. Later production composition must invoke that guard and the relevant admission checks; the marker alone does not attest adapter correctness.

## Atomic action and approval sequence

1. Validate envelope, current state/workspace, operation config, containment and test/data boundaries. Required finite limits include time/output/CPU/memory/PIDs/repair/review/tokens/cost as applicable; absence/invalidity fails closed before constrained effects. Replan cap is three after initial plan. The trusted configuration has a version; lowering limits can exhaust allowances, loading it cannot replenish them.
2. Normalize executable/argv/working-directory or patch identity; UC-05 classifies and validates policy identity. Pause and persist pending action/decision through UC-04 when required. A forbidden action terminates with denial, irrespective of human intent.
3. Before dispatch, atomically revalidate state/binding and reserve required remaining allowance. If paused before reservation, reserve on approved resume. If a reservation already exists for that action ID, reconcile it rather than reserve/execute again.
4. Execute through the real isolated RepositoryPort only, without shell interpolation. Persist action identity/effect observations and settle consumed resources atomically through UC-04. Crashes leave the reservation charged; recovery inspects effects before any retry. Exact transaction mechanics are UC-04's responsibility.
5. Checkpoint transitions/evidence with CAS. Conflicts or changed repository/policy/action prevent replay; reevaluate. Time/output limits terminate process trees and truncate safe output while preserving outcome metadata.

This sequence is a consumer contract, not a replacement implementation of UC-04/UC-05. Owners must resolve durable dispatch/effect reconciliation details at T001.

## Repository-command view and write boundary

Tai's workspace/executor (T006) and repository tools (T007), composed by T022, enforce two authorities within each task workspace. The canonical repository is writable only by the trusted controlled-patch path, which runs no repository code, hooks or plugins while that authority is available. An approved repository command, including pytest, receives a separate immutable command view of the permitted repository content at `/workspace/repo`, mounted read-only; it never receives the writable canonical volume. Only task-specific scratch at `/workspace/scratch` is writable by repository code. Changing source/tests through any command is forbidden even when the command itself is allowed. New regression tests enter through controlled patching, not subprocess writes.

Before a command view is materialized, trusted admission excludes protected paths (.env, PEM/key/SSH/credential material), agent files, Git history containing protected content and hidden grading. Validate included file contents and resolved links before copying: reject protected content, links to excluded/outside targets and unclassifiable required files; do not first copy forbidden bytes into a container, snapshot, cache or diagnostic artifact. If a required source file contains an embedded secret, refuse the operation and report a sanitized prerequisite. Do not silently redact executable source and then claim verification of the original code. Dependencies must already be prepared in the approved read-only image and satisfy the same data boundary.

Record the canonical revision/worktree digest, included file digests, exclusions-policy version and command-view digest. Included executable source and tests must be byte-identical to the authorized canonical state; refuse if required checks depend on excluded files or if a view is stale. Serialize view construction with controlled patches or reject a version conflict. Every canonical change invalidates the old view/evidence; rebuild before the next command. UC-04 retains canonical workspace identity and view references across resume; a cached view cannot override drift validation.

Configure Python bytecode, pytest cache and temporary outputs to scratch (or disable them through approved argv/environment); no writable overlay over source/tests and no repository-to-scratch write-through links. Scratch artifacts are untrusted, are never automatically copied back or added to coder/reviewer context, and undergo content/access checks before any permitted use. If a legitimate check requires repository writes, report that unsupported prerequisite instead of granting a wider mount. Exact Docker mounts/flags remain T001/T006 choices, but read-only command views and absent protected content are mandatory invariants, proved by malicious-pytest C06/C08/C11 at T024/T031. A post-run digest comparison supplements, rather than replaces, prevention before effects.

## Host-provider budget protocol (coder and reviewer)

Host model calls do not execute through RepositoryPort. Tai's ModelPort (T008), used also by the reviewer (T009), must apply this separate consumer protocol using Thanh Tan's StatePort. It introduces no UC-03 persistence implementation or provider access in task containers.

1. Assign a stable providerRequestId tied to task/run, coder/reviewer role, call purpose, provider/model/configuration and pricing-policy identities, and an approved-context digest. Validate finite per-call timeout, input/output token caps and a conservative maximum billable token/cost bound, including provider-specific reasoning/cache/overhead billing. Missing, inconsistent, exhausted or unbounded configuration/accounting means zero provider dispatch. If a supported provider cannot enforce a cap and establish a conservative cost ceiling, refuse the call.
2. Before any provider network request, atomically and durably reserve all applicable task/run token and cost amounts through UC-04 under that request ID; reviewer calls also reserve an iteration. Partial multi-budget reservation must not authorize dispatch. A failed reservation sends no request. A new run ID, retry or reviewer role cannot replenish task allowances.
3. Dispatch once using the reserved envelope and enforce provider caps/deadline. Validate the response and settle all reservations against observed provider usage and the recorded pricing identity through UC-04, including usage from rejected/malformed responses. Estimates and telemetry are projections, never permission to spend or substitutes for the ledger. A configured retry is a separately identified and reserved call after the prior outcome is reconciled.
4. Timeout, crash or missing usage may still be billable: keep the unresolved reservation charged and mark the request uncertain. Do not blindly replay or release it because the client stopped waiting. UC-04 reconciles provider request/usage evidence under its recovery contract; only verified non-dispatch or accounted usage permits release/settlement. Where no reconciliation is possible, retain the conservative charge and report the limitation. Provider idempotency may be relied on only when explicitly supported and evidenced; unknown accounting prevents further constrained dispatch.
5. Checkpoint safe request identity, configured maxima, reservation/settlement refs, role, outcome and observed usage/cost without prompts, credentials or raw responses. T008/T009 mock tests and C10/C15 integration at T028/T030/T032 must assert zero calls on missing/exhausted allowance, independent reviewer budget enforcement, and durable charge/no duplicate call after termination between reservation, network dispatch and settlement.

## Fix-plan approval proposal

`approve_fix_plan` request binds task/workspace/repository state, planVersion, strategy digest, diagnosis/baseline evidence refs, criteria/check-set digest and policy ID/version. Human sees reproduction, cause/locations, scope and checks. Decision is stored only through UC-05/UC-04. Ordinary tool actions still require their own gate. A new regression test can be added during reproduction under tool/test policy before production edits; when it changes the approval-bound state, bind the plan to that resulting baseline state.

Material replan creates a unique proposal ID and consumes a reserved task slot, invalidates prior plan edit permission and requires renewed decision. Rejection enters await-feedback; no autonomous alternatives. Wording clarification preserves strategy binding only when its material fields are unchanged. T001 agrees materiality classification and exact binding with UC-05 rather than accepting a coder-supplied boolean as authorization.
